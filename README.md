# Планер

Десктопное приложение для Windows и macOS: страницы с заметками и задачами в духе Notion.
Работает офлайн, данные хранятся на вашем компьютере. По желанию — синхронизация между
компьютерами через собственный сервер (см. «Синхронизация»).

## Запуск для разработки

Нужны [Node.js](https://nodejs.org) (LTS) и git.

```powershell
npm install
npm start
```

## Сборка

| Команда | Результат |
|---|---|
| `npm run build:win` | `dist\Planer-Setup-<версия>.exe` — установщик Windows (выбор папки, ярлык на рабочем столе) |
| `npm run build:mac` | `dist/Planer-<версия>-universal.dmg` — только на Mac (Intel + Apple Silicon) |
| `npm run icon` | перерисовать `build/icon.png` из `build/icon.svg` |

### Сборка Mac-версии через GitHub Actions

На Windows собрать `.dmg` нельзя, поэтому есть workflow `.github/workflows/build.yml`.
Он собирает обе версии на серверах GitHub и прикладывает файлы к релизу.

1. Создайте пустой репозиторий на GitHub и отправьте туда проект:
   ```powershell
   git remote add origin https://github.com/<ваш-логин>/planer.git
   git push -u origin main
   ```
2. Поставьте тег версии и отправьте его:
   ```powershell
   git tag v1.0.0
   git push origin v1.0.0
   ```
3. Через 5–10 минут на вкладке **Releases** появится релиз `v1.0.0` с файлами `.exe` и `.dmg`.
   Ход сборки виден на вкладке **Actions**. Там же можно запустить сборку вручную
   (**Run workflow**) — тогда файлы будут в разделе **Artifacts** запуска.

Перед новым релизом увеличьте `version` в `package.json` (например, `1.0.1`) и поставьте тег `v1.0.1`.

### Предупреждения при установке (нет подписи кода)

Приложение не подписано сертификатом, поэтому системы покажут предупреждение:

- **Windows (SmartScreen):** «Система Windows защитила ваш компьютер» → нажмите
  **Подробнее** → **Выполнить в любом случае**.
- **macOS (Gatekeeper):** «Не удаётся открыть приложение…». Перетащите «Планер» в «Программы»,
  затем в Finder щёлкните по нему правой кнопкой → **Открыть** → **Открыть**. Если кнопки нет
  (macOS 15+): **Системные настройки → Конфиденциальность и безопасность** → внизу
  **Всё равно открыть**. Либо в Терминале:
  `xattr -dr com.apple.quarantine "/Applications/Планер.app"`

Это нужно сделать только при первом запуске.

## Где лежат данные

- Windows: `%APPDATA%\Планер\`
- macOS: `~/Library/Application Support/Планер/`

Там находятся:
- `data.json` — все страницы и задачи (запись атомарная: сначала во временный файл, потом замена);
- `backups/data-ГГГГ-ММ-ДД.json` — резервная копия раз в день, хранятся последние 14;
- `window-state.json` — размер и положение окна;
- `sync.json` — адрес сервера и ключ синхронизации;
- `sync-state.json` — служебные отметки синхронизации (время изменения записей, удалённые записи).

Если `data.json` повреждён, приложение отложит его как `data.corrupt-….json`, восстановит данные
из последней резервной копии и сообщит об этом. Открыть папку данных: **Справка → О программе →
Открыть папку данных**.

Экспорт и импорт всех данных в JSON: меню **Файл** или кнопки внизу боковой панели.

## Синхронизация

Задачи и заметки можно синхронизировать между компьютерами (Windows и Mac) в реальном времени
через свой сервер. Аккаунтов и сторонних облаков нет: сервер хранит общую копию, приложения
подключаются к нему по защищённому WebSocket (WSS) с ключом доступа.

**Как устроено.** Данные раскладываются на записи — каждая страница и каждая задача отдельно,
у каждой время последнего изменения. Правки разных задач на разных компьютерах не мешают друг
другу; если одну и ту же задачу изменили в двух местах, остаётся более поздняя правка.
Удаления запоминаются. Без связи приложение работает как обычно, а при подключении
обменивается с сервером всеми изменениями. Тема, выбранная страница и т.п. у каждого
компьютера свои. Логика слияния — `src/sync-core.js`, она общая для приложения и сервера.

**Подключение.** Значок ☁ внизу боковой панели (или **Файл → Синхронизация…**): адрес сервера
(например, `203.0.113.5:8443`) и ключ доступа. Точка на значке: зелёная — всё синхронизировано,
жёлтая — подключение, серая — нет связи, красная — ошибка (например, неверный ключ).
На втором компьютере при первом подключении отметьте **«Заменить данные на этом компьютере
данными с сервера»** — иначе данные компьютера и сервера объединятся.

### Сервер

Код — в папке `server/` (Node.js + библиотека `ws`), запускается в Docker:

```bash
# в корне репозитория на сервере
docker build -f server/Dockerfile -t planer-sync .
mkdir -p /opt/planer-sync/data
echo "PLANER_TOKEN=$(openssl rand -base64 33 | tr '+/' '-_' | tr -d '=\n')" > /opt/planer-sync/.env
chmod 600 /opt/planer-sync/.env
docker run -d --name planer-sync --restart unless-stopped -p 8443:8443 \
  -v /opt/planer-sync/data:/data \
  -v /путь/к/сертификату:/certs:ro -e TLS_CERT=/certs/fullchain.pem -e TLS_KEY=/certs/privkey.pem \
  --env-file /opt/planer-sync/.env planer-sync
```

- Ключ доступа — значение `PLANER_TOKEN` в `/opt/planer-sync/.env`.
- Нужен сертификат, которому доверяет система (например, Let's Encrypt). Обновлённый
  сертификат сервер подхватывает сам (проверка раз в час).
- Данные сервера: `/opt/planer-sync/data/store.json`, ежедневные копии — в `data/backups/`
  (хранятся 30 последних).
- Проверка: `https://адрес:8443/` отвечает «Планер: сервер синхронизации работает»,
  журнал — `docker logs planer-sync`.

Обновить сервер: скопировать новые `server/` и `src/sync-core.js`, пересобрать образ и
пересоздать контейнер той же командой `docker run` (данные и ключ сохранятся).

## Горячие клавиши

На Mac вместо Ctrl — ⌘.

| Клавиши | Действие |
|---|---|
| Ctrl + N | Новая страница |
| Ctrl + K | Быстрый поиск по страницам и задачам |
| Ctrl + \ | Скрыть / показать боковую панель |
| Ctrl + Shift + L | Светлая / тёмная тема |
| Ctrl + Shift + E | Экспорт |
| Ctrl + O | Импорт |
| Ctrl + = / Ctrl + − / Ctrl + 0 | Масштаб |
| F11 (Mac: Ctrl + ⌘ + F) | Полноэкранный режим |
| Esc | Закрыть панель задачи / поиск |
| «- » в начале строки заметки | Маркированный список |

На Windows строка меню скрыта — нажмите **Alt**, чтобы её показать.

## Возможности

- Дерево страниц: создание, подстраницы, перетаскивание (выше / ниже / внутрь), избранное.
- Заметки на каждой странице, задачи списком или доской (Сделать / В работе / Готово).
- У задачи: срок, время, приоритет, напоминание (системное уведомление; клик открывает задачу),
  описание и подзадачи — в панели, которая открывается по щелчку на свободном месте строки задачи.
- Разделы «Сегодня» (просрочено, сегодня, 7 дней) и «Все задачи».
- Календарь (иконка 📅 внизу боковой панели) в стиле Google Календаря: виды «Месяц» и «Неделя»,
  задачи стоят по своему сроку и времени. Щелчок по пустому дню или часу — новая задача,
  перетаскивание задачи на другой день/час меняет срок, щелчок по задаче открывает её.
- Удаление страниц и задач можно отменить в течение 5 секунд.

## Структура

```
src/main.js          главный процесс: окно, меню, диалоги, напоминания
src/storage.js       чтение/запись data.json, резервные копии
src/sync.js          синхронизация с сервером (главный процесс)
src/sync-core.js     слияние данных — общее для приложения и сервера
src/preload.js       мост window.api между интерфейсом и главным процессом
src/renderer/        интерфейс: index.html, styles.css, app.js, calendar.js, sync.js
server/              сервер синхронизации (Node.js, Docker)
build/               иконка (icon.svg → icon.png)
prototype/           исходный прототип (для справки)
```

Формат данных имеет поле `version` (сейчас 2). При изменении формата добавляйте шаг в
функцию `migrate()` в `src/renderer/app.js`.
